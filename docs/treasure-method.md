## この文書の役割

探索法の**叙述の正本は My Portal の Intelligence Pack `treasure-keyword-intelligence`（v2）**にある。
Pack は不変バージョンで、resolver が正確な版を固定して注入できる。手法を変えるときは Pack を v3 に上げる。

この文書は、その手法を **CI で検査できる契約**に落としたミラーである。

- 不変条件のID（I1–I7）
- コードが返すべきフィールド名
- `methodVersion` の記録義務
- Pack 側の版との対応（このヘッダの `CANONICAL` 行）

`scripts/treasure-method-contract-smoke.ts` が、この契約とコードの一致を検査する。
**Pack を更新したら、この文書のバージョン行と CANONICAL 行も同じ run で更新する。** 片方だけ直すと次の run が古い版を読む。

## 2. 発見元（どこから名前を採るか）

**発見元は「名前の在庫」を作るだけで、お宝かどうかは決めない。** 採った後の2工程が本体。

- 一次発生源：新製品・新サービス発表、発売告知、公示、開業予定
- 制度・規格：認定制度、資格、規格の新設・改定、様式名、区分名
- 供給体系：メーカーの製品体系、行政の制度一覧、学会の用語体系
- 市場在庫：ECの実在商品名、商品コード、ランキング
- 当事者の言葉：Q&A・レビューで反復する呼称・困りごと

**採った直後に必ず2つを通す。**

1. **識別性**：同名の別対象が上位に居ないか（例：ティンブロの需要3,600/月はレストランだった。カモンマイハウスは競走馬・曲・漫画と衝突）
2. **需要帰属**：その需要が自分の対象のものか

## 3. 判定（コードが返す値を読む）

| フィールド | 何を意味するか | 使い方 |
|---|---|---|
| `purchaseIntent` / `purchaseIntentScore` | 語形から見た購買局面（transaction/comparison/evaluation/informational） | SERP予算の配分にだけ使う。証拠にしない |
| `commercialIntentScore` | 語形 × CPC | 資金の見込み。競合の代用にしない |
| `coreCoverage` / `competitionLevel` | 汎用修飾語を除いた核を1ページ目が被覆している割合 | **high は記事では入れない** |
| `toolPageCount` / `toolGap` | 計算・診断・チェックリスト・早見表の有無 | 道具の空白。**競合の不在ではない** |
| `answerGap` / `termCoverage` | 1ページ目がその組み合わせに答えているか | 補助信号。表記ゆれに弱い |
| `editorialSlot` / `composition` | 単一運営者の独占か、複数供給者か | 参入構造 |

## 4. ゲート順（この順で落とす）

1. **G0 実在**：公式一次資料で名称を同定できるか
2. **G1 識別性**：同名別義に食われていないか
3. **G2 需要**：対象国・言語を固定して測ったか。欠損は Hold（I6）
4. **G3 競合**：`competitionLevel` が high なら棄却（I3）。medium は意思決定クエリ限定
5. **G4 商流**：誰にいくら払うか。商流の不在は Lane B の棄却理由にしない（Hold）
6. **G5 勝ち筋**：記事で入れるか、道具/LPで入れるか。ここが空欄なら作らない

## 5. to C と to B で何が変わるか

同じ手順を使うが、**勝ち筋の設計が違う**。

### to C（消費者）

- **需要は測れるが、競合は必ずいる。** 月20回の語にも10社が書いている（実測）
- 競合の正体は業者の営業記事とアフィリエイトサイト。**読み物では勝てない**
- 勝ち筋は2つだけ：
  - **道具**：計算機・簡易診断・早見表・チェックリスト（例：空き家解体費の概算、永代供養費の総額計算）
  - **一次データ**：自分の実測・実購入・実体験（他人が複製できない）
- 金額が極端に広い語（10万〜150万など）ほど道具が効く。条件を入れて絞る需要が必ずある
- YMYL（医療・死・相続・住宅）は断定的表現を禁止し、一次資料の引用に限定する

### to B（事業者・担当者）

- 競合は行政書士・社労士・コンサル・SaaSのコラム。**さらに強い**
- 需要は検索量で測れないことが多い（月20以下）。**Lane C で証明する**
- Lane C の需要根拠：義務（法令上の手続き）、供給（買える場所がある）、記録（導入実績・認定件数）、当事者の行動（同じ質問の反復）
- 勝ち筋は**手順の完全性**：様式別の必要書類、期限の時系列、差し戻しの典型、窓口ごとの差異

## 6. run の記録義務（手戻り防止）

各 run は `operation_checkpoint` と treasury の `evidence` に次を残す。

- `methodVersion`: `tsk-v8` のような文字列
- レーン内訳：Lane B（受け皿非依存）／Lane A（受け皿先）／Lane C（測定不能）
- `competitionLevel` と `toolGap` の実測値
- 棄却理由（どのゲートで落としたか）

**記録が無い候補は次回 Qualified にしない。** これが無いと、同じ語を別の言い方で再発見して同じ判断を繰り返す。

## 7. 既知の天井（手法では解決しないこと）

- **Google SERP が取れない**とき、競合判定は Brave 観測。順位の同一性は保証されない
- **Ads の測定下限（月10前後）**より下は、需要を検索量で証明できない
- **ドメインの強さ**は測っていない。`competitionLevel` は「1ページ目が核を被覆しているか」だけを見る
- 記事の質・更新年・被リンクは見ていない
