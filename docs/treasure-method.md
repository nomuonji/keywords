# Treasure keyword discovery — canonical method

**METHOD VERSION: tsk-v13** (2026-11-10)
**CANONICAL: my-portal intelligence_pack `treasure-keyword-intelligence` v7**

## この文書の役割

叙述の正本は My Portal の Pack（v7）。ここは CI で検査する契約（不変条件ID・コードのフィールド名・`methodVersion` 義務・Pack版ポインタ）。

**主手順は既存スキル `niche-keyword-finder`**（一次発生源 → サジェスト展開 → 実在確認 → allintitle → SERP弱さ採点 → 受け皿の作り分け）。この Pack はその上に重ねる差分だけを持つ。**新しい体系を作らない。**

| ゲート | 内容 | 根拠 |
|---|---|---|

| **非自明性（I13）** | 一次資料にのみ存在し、事前分布から列挙できない名前 | 補助金判定・諸費用・引越し実費はどのAIも出す（指摘） |

## 3. 手順

1. パターン集（My Portal Context `ebMQtOD84CHjY4MwNXDx`）とサイトの強さを確認
2. 一次発生源から名前を採る（PR TIMES／クラファン／発表告知／公的資料）
3. カテゴリ名を落とし、状況＋対象＋条件へ切り直す（I16）
4. サジェスト展開（plain / wildcard_pre / question / suffix）
5. 需要は Ads とサジェストの両方で見る。**Ads null は未知**（I18）
6. 競合は allintitle・枠の弱さ（6点で着手）・専用ページ2件で飽和判定。官公庁・大手が並べば見送り
7. 収益密度を見る。1成約1,000円未満は棄却（I17）
8. 受け皿を決める（場面ページ → 既存H2 → 新規URL の安い順）
9. methodVersion・cycleId・パターン・棄却ゲートを記録して保存、readback

## 4. 既知の天井

- サジェストは「誰かが検索した」ことを示すが、量は示さない
- allintitle はブラウザか総件数を返すAPIが必要。この環境では取れないことが多い
- SERPプロバイダが枠切れのとき、飽和は判定できるが「空き」は判定できない
- 収益密度の報酬率は公開されていない。仮定と明記する
- AIO の有無はこの環境から測れない
