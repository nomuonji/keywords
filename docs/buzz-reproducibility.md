# バズの再現性：システム設計（2026-11-03 実測にもとづく初版）

この文書は、「バズる企画を出す」を一回ごとのセンスではなく、試行回数と選別の確率で回る仕組みとして設計する。根拠は 2026-11-03 の実測（下記）で、まだ一回の観測にすぎない。数字は更新する前提で読む。

## 1. 何を「再現性」と呼ぶか

1件のバズを再現することはできない。再現できるのは、**1回の試行あたりの当たる確率**と、**当たりを早く見つけて伸ばす速さ**だけである。

```
1日あたりの当たりの数 ＝ 試行の数 × 型ごとの当たる確率 × 早期選別の精度
```

この3つの項を、それぞれ別の部品で測って上げる。総合スコアは作らない。

## 2. 2026-11-03 の実測

| 観測 | 値 | 意味 |
| --- | --- | --- |
| バズ投稿（いいね3,000以上、lang:ja、直近1〜2週）| 256件 | X検索 Top。投稿者70人ぶんのタイムラインを基準値として取得 |
| そのうちフォロワー5,000人未満のアカウント | 86件（34%）| バズの3分の1は、フォロワーがほぼいないアカウントから出ている |
| 型ごとの小規模アカウント比率 | 内部者の暴露 83%、身内の小さな出来事 57%、一行 54% ／ 時事への反応 19%、告知 3% | フォロワーに依存しない型と、依存する型がはっきり分かれる |
| 同じ型の普通の投稿（「妻が・夫が・娘が・息子が」、1日分、約5日経過）| 320件中、いいね1,000以上は1件（0.3%）、中央値5 | 型を真似るだけでは、ほぼ当たらない |
| 文面だけでバズを当てる盲検テスト（バズ14件 vs 普通291件）| AUC 0.986（上位10件中8件がバズ）| AIは、バズれる品質と凡庸な投稿をかなり正確に区別できる |
| 同じテストの偽陽性 | 家族の掛け合いにオチがある投稿が、いいね0〜14で上位に入った | 品質の高い投稿でも、伸びないものがある |

結論は3つ。

1. **品質の下限はAIで判定できる。** 凡庸な投稿を落とすことには、AIの判定を使ってよい。
2. **品質を満たした候補の中で、どれが当たるかは文面からは決まらない。** これを決めるのは、実際に出した後の反応だけである。
3. **型の当たる確率は、勝った投稿だけ見ても分からない。** 分母（同じ型の、伸びなかった投稿）が必要である。

## 3. 部品

| 部品 | 役割 | 現状 |
| --- | --- | --- |
| A. バズ台帳 | バズ投稿を、エンゲージメントの実数・投稿者の基準値（いつもの中央値）・過剰反応倍率つきで継続的に蓄積する | 無い（今回は scratchpad の単発 script）|
| B. 分母台帳 | 型ごとに、伸びなかった同型の投稿を同じ条件で標本化し、型ごとの当たる確率を出す | 無い |
| C. 型の辞書 | 型（構造×感情×フック）と、その確率・フォロワー依存度・制作に必要なもの（実際の出来事・映像）を持つ | 無い。`marketing-techniques` に近いが、確率と分母が無い |
| D. 品質の下限フィルタ | 生成した候補から凡庸なものを落とす。盲検テストを回帰テストとして定期的に再実行し、AUCを記録する | 今回のテストのみ。`idea-final-judge` は別目的で、較正されていない |
| E. 実地テスト | 自分たちのテスト用アカウントで、多数の候補を出す。最初の1〜2時間の反応をアカウントの基準値と比べ、上位だけを伸ばす（再投稿・記事化・動画化）| 一部あり。Tweets（nomuonji/tweets）が投稿ごとに構造を分類し、構造別のエンゲージメント率中央値を週次で集計し、探索率（既定0.2）で新しい構造を試している。早期の選別・増幅と、外部のバズ台帳との接続は無い |
| F. 学習 | E の結果で、C の確率（自分たちのアカウントでの値）と D の判定精度を更新する | 一部あり。Tweets の週次学習が、成功した構造・話題を生成プロンプトへ戻している。Keywords 側のバズ台帳・型辞書・判定精度へは戻らない |
| G. 本人の好みの関門 | 市場でのバズとは別の軸として、本人のGOOD/ボツを記録する。両者がどれだけ重なるかを測る | Idea Memory が担っているが、市場の実測と混ざっている |

Keywords 側で回っているのは、G（本人の評価）と、較正されていない D だけである。E・F の原型は Tweets 側にあるが、外の市場の観測（A・B）とつながっていないので、自分のアカウントの過去の勝ちパターンの中でしか学習できない。

## 4. 誠実さの境界

身内の小さな出来事・目撃談・内部者の暴露は、フォロワーに依存しない強い型だが、**実際に起きた出来事が無ければ作れない**。架空の体験談を一人称の事実として投稿することはしない。AIのアカウントでこれらの型を使うのは、次の場合に限る。

- 実在する公開投稿の紹介・引用（出典つき）
- 人格がAIまたは架空であると明示されたアカウントでのフィクション
- 本人（運営者）が実際に体験した出来事

この境界の中で取れる型（一行・あるある、豆知識、時事への反応、自前の映像）から始める。

### 知恵袋などの実在の体験談を素材にする場合（2026-11-03 検討）

実在の体験談を素材にすれば、「出来事が本当に起きたか」の問題は解ける。ただし、「この投稿者自身が体験した」という主張は依然として偽になる。加えて、他人の体験を自分の話として出すと、元の書き手への剽窃と、本人特定のリスクが生じる。そこで、主張と出典の関係によって3つに分ける。

| 形式 | 例 | 扱い |
| --- | --- | --- |
| 目撃・紹介型 | 「知恵袋で見た相談が忘れられない。〜」（要約は自分の言葉で、引用は短く、元URLを返信欄などに置く）| 可。今回の実測で目撃談は小規模アカウント比率50%で、フォロワーに依存しない型に入る |
| 開示済みの人格による再話 | 人格がAIまたは架空だとプロフィールで明示したアカウントが、複数の実例を合成した話を語る | 可。合成であること、実例にもとづくことをプロフィールで開示する |
| 無開示の一人称 | 普通の個人アカウントとして「昨日うちの妻が〜」と、他人の体験を自分の体験として出す | 不可 |

「誠実さを守るとバズらなくなるか」は、推測ではなく実測で決める。実験用アカウントで、同じ素材を目撃・紹介型と開示済み人格型で出し、基準値に対する過剰反応倍率を比べる。

## 5. 次の検証

1. **より難しい盲検テスト：** バズ投稿と、「品質は高いのに伸びなかった投稿」（同じアカウントの普段の投稿や、偽陽性の類）を比べる。ここでAUCが0.5に近ければ、2.の結論（選別は実地でしかできない）が確定する。
2. **本人の好みとの重なり：** バズ台帳から30件を本人に見せてGOOD/ボツを付けてもらい、市場のバズとの一致率を測る。
3. **A・B を command にする：** script を `packages/research`（取得）と `packages/commands`（保存・runs 記録）に移し、継続的に貯める。
4. **E の最小形：** テスト用アカウント1つで、型ごとに10件ずつ出し、基準値に対する過剰反応倍率を測る。投稿は外部への公開なので、始める前に本人の承認を取る。
