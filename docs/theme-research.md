# SEO収益テーマ継続リサーチ

## 目的

Keyword Operator で、収益化候補テーマを「一度スコアリングして順位を決める」のではなく、セッションをまたいで批判検証し続ける。

正本の research session は `seo-theme-research`。

新しいChatGPTセッション、スケジュールタスク、別エージェントは、まず `theme_research_context` を読む。過去チャットの再構築から始めない。

## 原則

- 総合点、ランキング点、機械的な勝者選定は作らない。
- 検索量、成果単価、EPC、確定率、SERP構成、成果発生実績などは「観測事実」として保存する。
- 数値は判定そのものではない。検索意図のズレ、更新負荷、広告主依存、規約、実装難度などの質的な弱点を必ず併記する。
- 生存候補には必ず「なぜまだ残るか」「致命傷候補」「未確認点」「次に何を疑うか」を持たせる。
- 毎回、既存候補を擁護するより先に反証を探す。
- 強い代替候補を見つけたら追加し、既存候補と同じ土俵で批判する。
- killed の候補は消さない。死因を残し、新しい証拠がない限り同じ案を再提案しない。
- `pilot_ready` は「複数ラウンドの反証後も残った理由を文章で説明できる」状態。数値の閾値だけで昇格させない。
- challenge history は推論の逐語記録ではなく、攻撃点・証拠・結論・次の検証という外部利用可能な要約だけを保存する。

## 状態

- `surviving`: 現在も候補として残る。
- `challenged`: 重大な疑義があり、次の検証待ち。
- `parked`: 条件変更や追加情報待ち。
- `killed`: 現時点では狙わない。死因を保存する。
- `pilot_ready`: 小規模な実地テストへ送ってよい。

これは順位ではない。

## 1回のリサーチの基本

1. `theme_research_context` を読む。
2. 前回未解決の `nextChallenge` を優先して調査する。
3. 少なくとも1候補に対して、前回とは異なる角度の反証を行う。
4. 有力な代替テーマが見つかった場合は `theme_candidate_upsert` で追加する。
5. `theme_candidate_challenge` に攻撃、証拠、反証、結論、次の疑問を保存する。
6. killed にした理由は削除しない。
7. セッション終了時点で、次回がチャット履歴なしでも再開できる状態にする。

## 保存する観測事実の例

- 「A8公開ページで2026年8月に100件以上成果発生」
- 「新規資料請求 15,000円」
- 「Google Ads推定月間検索 1,900」
- 「SERP上位10件に知恵袋・noteが3件」
- 「成果条件は新規契約後30日利用」
- 「商標キーワードでの広告掲載条件は未確認」

これらを合算して独自の総合スコアにしない。

## スケジュールタスク向け

タスク本文には最低限、次を含める。

> Keyword Operator の `theme_research_context` を最初に読み、正本 `seo-theme-research` の続きから作業する。既存候補を批判検証し、必要なら新規候補を加える。総合スコアや固定ランキングを作らず、観測事実・致命傷・未確認点・次の反証を更新する。各実行で最低1件は `theme_candidate_challenge` を残す。新しい証拠なしに killed 候補を復活させない。
